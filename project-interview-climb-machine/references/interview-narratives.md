# Interview Narratives

## Shared rule

Start from the candidate's own current plan or attempt. Do not impose STAR or
another fixed framework. A framework may be offered as one option only when the
candidate needs structure and chooses it.

Keep each coaching round focused on the two or three changes with the highest
impact. Treat familiar products, papers, and technologies as accurate
connections, not prestige labels. State meaningful similarities and
differences; never imply the candidate built something they did not.

## M6 — Layer 1

Clarify the user's desired first impression and available time. Help the
candidate decide:

- what the project is;
- what the interviewer should understand first;
- what the candidate wants to say they did;
- which result or evidence matters;
- which truthful hook invites deeper discussion.

These are prompts, not mandatory template fields. Produce wording only after
the user establishes an approach. When reviewing a one-project slide, prioritize
rapid comprehension and visual hierarchy. Read the actual deck only with
material-reading permission.

## M7 — Layer 2

Ask for the user's preferred story line, outline, or natural narration first.
Help correct missing context, confusing order, unsupported claims, or technical
explanations that the intended interviewer may not follow. Preserve the user's
chosen emphasis.

Offer alternative orderings only when useful, and explain the trade-off
briefly. Do not automatically turn the project into a chronological report or
an AI-authored polished speech. Generate a full script only when requested
after the direction is confirmed.

## M8 — Layer 3

Ask which areas the user expects, worries about, or wants to explore. Build
question branches around those areas and around claims actually exposed by the
user's intended narrative. When the user wants questions derived from M7, read
the confirmed M7 section first.

Let the user answer before providing an improved answer. Explain why a question
may matter, correct the smallest important issue, and allow the user to decide
the final response. Do not overwhelm the user with a comprehensive generic
question bank.

## M10 — Multi-project introduction

Work in `portfolio.md`. Ask for the user's current project selection, order, and
time allocation. Help refine the overall progression and transitions without
choosing a portfolio on the user's behalf. Read each selected project's minimal
base; read its M6 section only when it exists and is relevant.

Keep different company or role variants as sections in the same `portfolio.md`.
Do not create per-role files or directories.
